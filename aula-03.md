# O Princípio F.I.R.S.T.

## first é uma combinação de varios princípios. 

- F ast - os testes unitários devem executar rapidamente;
- I ndepent - os testes unitários devem ser independentes uns dos outros. usando dados mockados ou prefefinidos;
- R epeatable - os testes unitários devem ser repetidos, o mesmo resultado deve ser validado mesmo  testando varias vezes ou em computadores diferentes, ambientes e SO diferentes;
- S elf-validating - os testes unitários devem se auto validarem, não podendo o dev fazer verificações manuais;
- T hrough & Timely - os testes unitários devem cobrir casos extremos, Caminho Feliz e Negativo, testar valores minimos e maximo, melhor testar quando criar a funcionalidade;
